Unity Japanese Localization Checklist

This checklist is for teams importing English/Japanese UI strings into Unity Localization String Table Collections. It catches cheap data errors before visual and linguistic review.

CSV baseline: Unity Localization supports CSV import/export for String Table Collections. Official documentation describes columns such as Key, Id, and locale columns like English(en) and Japanese(ja). For new entries, an empty or 0 Id can be used so Unity assigns an ID.

Before import

  1. Keep stable, descriptive keys.
  2. Verify every required Japanese value exists.
  3. Compare runtime placeholders/tokens between English and Japanese.
  4. Check copied spreadsheet text for leading/trailing whitespace and invisible characters.
  5. Review half-width katakana and U+3000 spaces intentionally.
  6. Review explicit Japanese line breaks for kinsoku risks.
  7. Flag unusually long strings for later layout inspection.

Import and merge

  1. Use the String Table Collection CSV import workflow.
  2. Choose replace versus merge intentionally; merge is useful when updating only entries present in the CSV.
  3. For new entries, leave Id blank or use 0 if you want Unity Localization to allocate IDs.
  4. After import, inspect a few representative tables before assuming the whole batch is correct.

In-context checks

  1. Test the actual Japanese font and fallback stack.
  2. Test narrow buttons, settings rows, pop-ups and subtitle areas.
  3. Exercise variables with realistic longest values.
  4. Review component-level wording consistency rather than enforcing one Japanese register globally.
  5. Run linguistic and visual LQA before release.
