Godot Japanese Localization Checklist

This checklist is for indie teams moving English/Japanese UI strings through Godot’s CSV localization workflow. It separates engine-format correctness from Japanese-language and visual QA.

Engine baseline: Godot’s spreadsheet localization workflow supports CSV. The official documentation specifies UTF-8 without BOM, a first column of string identifiers, and locale-code headers such as en and ja.

Before import

  1. Keep every translation key unique and stable.
  2. Use a CSV header such as keys,en,ja.
  3. Save the CSV as UTF-8 without BOM.
  4. Check that runtime placeholders match between English and Japanese.
  5. Flag empty Japanese values before they enter the engine.
  6. Review explicit Japanese line breaks for kinsoku problems.
  7. Look for accidental half-width katakana, U+3000 spaces and punctuation-style mixing.

After import

  1. Confirm the CSV importer generated translation resources.
  2. Confirm translations are configured/loaded by the project rather than assuming import alone is enough.
  3. Exercise menus at the smallest supported UI size.
  4. Test variables at realistic maximum lengths: player names, item names, counts and time values.
  5. Run visual LQA in the actual font and container widths.

Why preflight before Godot?

Many localization defects are data problems, not engine problems. A placeholder mismatch or invisible spacing issue is cheaper to catch before opening the game. Japanese-specific typography risks can also be surfaced early, while still leaving semantic wording and context to human review.
